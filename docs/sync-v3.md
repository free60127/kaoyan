# 同步协议与发布检查

云端 `kv_store` 保存带因果版本的同步文档；不需要修改现有表结构或 RLS 策略。错题记录及学习备份新增可选 `wrongCounts` 设备计数，继续兼容没有该字段的旧记录及旧备份。

## 云端记录

每台设备写入自己的行：`yantu-sync-v3:<编码后的业务键>:<编码后的设备 ID>`。例如电脑和手机的 SRS 快照分别保存，不会同时覆盖同一行。客户端读取同一账号的所有设备行，合并每个字段的版本。一个设备成功上传后即可离开，其快照仍能被另一端读取。

`value` 形状为 `{ protocol: "yantu-sync-v3", cells: { 路径: [{ clock, value, deleted? }] } }`。路径是 JSON 字符串数组，clock 按设备保存递增序号，不依赖客户端时间。配置、认证信息、API 密钥和设备 ID 不在业务同步白名单内。

## 合并规则

- 后续编辑观察并取代已有版本，包括撤销、取消标记、删除、恢复错题。
- 同一份草稿、同一题答案、个人卡片文字的并发修改保留双方文字；富文本合并时平移样式偏移。超过业务文字长度上限时展示一个完整分支，双方原稿仍可导出。
- 不同卡片、不同题目、不同字段独立合并。统计按设备桶累计；自己桶内的扣减可以传播。错题计数按设备拆成独立因果寄存器，观察旧值后的撤销覆盖自己桶，其他设备的新增错误仍保留。旧版整个错题条目的寄存器会拆分并保留因果版本。并发明确删除错题优先；撤销仅恢复旧删除状态时不隐藏另一端的新答错。零计数保留供同步，界面不显示为错题。手动标记待复习不增加错误次数。
- 复习范围按书目、章节、小节拆成独立成员；并发暂停第一章、加入第二章时只保留第二章。读取早期 v3 的多章节成员时拆分并保留因果版本。卡片并发重置与旧评分以重置为准，旧评分仍在冲突原稿中。
- 合并顺序使用固定字符串顺序，不受电脑和手机的语言设置影响。富文本样式按去除教材标记后的文字长度平移；合并超过 400 个样式区间时保留一个有效分支和双方原稿。
- 同一张卡的并发评分、不同样式或其他非文字冲突采用确定性分支，并保留未选中的版本。同步面板提示冲突，可导出包含版本文档的原稿；检查后编辑为期望内容。相同字段再次发生实际修改时，冲突版本被该修改取代。
- 学习页面位置和模拟卷答题光标留在本机。今日准入不混入其他日期；活动记录和其同步元数据均保留最近 300 项。

## 确认与账号隔离

元数据一次写入包含文档、应用基线和待传键，单独队列索引仅作辅助。上传成功只确认发送时的版本，上传期间产生的新修改继续排队。下载写入失败不确认完成，自动重试。Realtime 将收到的行放入同一个串行执行器；5 秒检查本地改动，15 秒拉取用于断线补偿。下载按键排序，每次请求最多 500 行，按实际返回数量推进，并根据服务端总行数继续读取；服务端上限低于 500 时也会读取后续记录。全部分页成功后才应用；后续页面失败或意外空页会报告错误并重试。

账号分区包含业务记录、同步文档和队列；配置与设备 ID 独立保存。首次访客登录可带入访客学习数据，此后访客和各账号互相独立。身份切换会失效旧请求、重载页面状态、取消未完成的 AI 请求和个人卡编辑。升级旧版已登录会话时采用当前数据，避免恢复旧的登录时快照。退出使用 Supabase 的 local scope，仅撤销当前设备会话，其他设备可以继续刷新令牌；退出失败会反馈到页面。

切换账号时若部分写入后存储失败，会移除目标账号刚引入的键并恢复原账号记录。配置 URL 仅接受 HTTPS 的真实 `项目编号.supabase.co` 主机，拒绝相似域名及内嵌凭据，保存为项目源地址；保存失败在页面显示错误。
